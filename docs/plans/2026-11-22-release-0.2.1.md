# Release 0.2.1 — Plan

**Goal:** publish 0.2.1, a patch release that ships the dependency updates merged since 0.2.0 and exercises the updated release tooling, through the normal process: release pull request → release candidate → home-lab test → promotion.

**Why (owner decision, 2026-11-22):** `main` carries dependency fixes that the published 0.2.0 image lacks (`jiff` 0.2.46 with the `jiff-core` unsound-API fix, `zeroize` 1.9.2, lock-file maintenance), and the release tooling changed since the last tag (Rust 1.100, `cargo-deny` 0.22, `syft` 1.57.2, `grype` 0.122.1, `oras` 1.4.0, BuildKit 0.35.1). A calm release proves the pipeline before an urgent one needs it. No API or behaviour change.

**Process sources:** `docs/development.md` ("Bump the versions", "Tag", "When a release run fails", "Verify a release"); ADR 0004 (release gate from main CI) and ADR 0005 (promote release candidates); `docs/installation.md` "Verify the release"; the home-lab procedure and scenario list in `docs/releases/0.2.0-home-lab-test.md`.

## Constraints

- No API, CRD, chart-template or behaviour change. Only the version fields, the changelog and the documentation pins change in the release pull request.
- Tags are annotated, plain semver, never moved or deleted. Tag only a commit on `main` whose push-triggered CI run is green.
- A final release promotes the candidate on the same commit (no `rebuild:` line).
- No commit SHAs in documentation (changelog, release report): name versions, image digests only where verification needs them.
- Never print Secret values in reports. Values generated in the throwaway test namespace may be compared by fingerprint (hash) only.
- Never run `gh auth token`; no force pushes.
- Home lab: kube context `admin@k8s`, Flux repository `/Users/jabbas/Projects/flux-home-system` (direct commits to `main` are the norm there). After pinning a new chart version, reconcile the HelmRepository `jabbas` before the HelmRelease. Reconcile `authentik` and `victoria-metrics` if they lag.

## Steps

### 1. Release pull request (STOP for review)

Branch `release/0.2.1` from `origin/main` in this worktree.

- "Bump the versions" items 1–5 from 0.2.0 to 0.2.1: `[workspace.package] version` (then `cargo build` so `Cargo.lock` follows), Chart `version`, `appVersion`, `artifacthub.io/images` tag, and every documentation pin listed in item 5 (verify blocks `TAG`/`CHART_VERSION`, `--version` in README, `docs/installation.md`, the chart README, Flux examples incl. the `subject:` regex `0\\.2\\.1$`).
- `CHANGELOG.md`: new section `## 0.2.1 - <release date>` (date filled when promoting is fine, or "Unreleased" now and dated in step 5 — follow the file's existing convention). Content: Changed — Rust toolchain and minimum supported Rust version 1.100; dependency updates (`jiff` 0.2.46 incl. the upstream unsound-API fix, `zeroize` 1.9.2, `clap`, lock-file maintenance); release tooling updates (`cargo-deny`, `syft`, `grype`, `oras`, BuildKit). Security — RUSTSEC-2026-0543 (`chrono`, unmaintained, test-only path) ignored with justification (link `docs/security.md`). Documentation — contributions from outside contributors (full label names, complete `oras` command), Artifact Hub listing. No commit SHAs.
- Gate locally: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo xtask crdgen --check`, `cargo xtask chart-test`, `cargo deny check`.
- Push, open the pull request "chore(release): 0.2.1", wait for CI green. **STOP: independent review, then the coordinator merges.**

### 2. Release candidate

- After the merge: wait for the push-triggered CI run on `main` to be green.
- `git tag -a 0.2.1-rc.1 -m 0.2.1-rc.1` on that commit, push the tag.
- Watch `release.yml` (build mode): every build-mode job green, `promote` skipped. On failure follow "When a release run fails" and STOP with the failing job and log excerpt.

### 3. Verify the candidate

Per `docs/installation.md` "Verify the release" and `docs/development.md` "Verify a release", anonymously:
- image `ghcr.io/jabbas/generated-secrets-operator:0.2.1-rc.1` multi-arch (amd64, arm64), labels (version, source), filesystem = binary + licences;
- `cosign verify` image and OCI chart with identity `…/generated-secrets-operator/.github/workflows/release.yml@refs/tags/0.2.1-rc.1`; `cosign verify-attestation` (SBOM) for both platforms;
- OCI chart renders image `:0.2.1-rc.1`; HTTP index lists `0.2.1-rc.1` with the same digest as the OCI chart layer and the release asset;
- grype scan passed in the run; GitHub pre-release with its assets; no `latest` tag;
- Artifact Hub must NOT show `0.2.1-rc.1` (ignore rule).

### 4. Home-lab test on the candidate

- `flux-home-system`: pin `generated-secrets-operator` to `0.2.1-rc.1`, commit, push; reconcile git source, `flux reconcile source helm jabbas`, the Kustomization; verify HelmRelease Ready on `0.2.1-rc.1`, pod 1/1, image digest equals the candidate's, logs clean.
- Run the scenario list a–l of `docs/releases/0.2.0-home-lab-test.md` in the test namespace `test-generated-secrets` (Pod Security `restricted`), with the same expectations; clean the namespace afterwards.
- Write `docs/releases/0.2.1-home-lab-test.md` in the same structure as the 0.2.0 report (versions, results per scenario, deviations; no commit SHAs, no Secret values). Merge it via a pull request (docs only).

### 5. Promote

- `git tag -a 0.2.1 -m 0.2.1 '0.2.1-rc.1^{commit}'`, push.
- Verify: release run "promoted from 0.2.1-rc.1" without rebuild; `:0.2.1` digest equals `:0.2.1-rc.1`; signatures verify with both identities (`refs/tags/0.2.1` and `refs/tags/0.2.1-rc.1`); SBOM attestations; chart 0.2.1 differs from the candidate only in `version`/`appVersion`; HTTP index and OCI chart digests agree; GitHub release marked Latest with notes starting at 0.2.0; no `latest` tag.
- If the changelog heading still says "Unreleased", date it in a small pull request.

### 6. After promotion

- `flux-home-system`: pin `0.2.1`, reconcile (HelmRepository first), verify HelmRelease, pod, digest, logs.
- Artifact Hub: after the next processing run, the package shows 0.2.1 as latest, Signed, no candidates.
- Website: unpinned install resolves to 0.2.1 (`helm repo update jabbas` + `helm search repo jabbas/generated-secrets-operator`).
- Final report to the coordinator.

## STOP points

1. After step 1 (release pull request open, CI green): independent review and merge.
2. Any red job in a release run, any verification mismatch, or a failing home-lab scenario: stop and report; do not tag further.
