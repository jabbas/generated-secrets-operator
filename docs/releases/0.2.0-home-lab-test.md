# 0.2.0-rc.2 home-lab test report

Home-lab test procedure of the design (§12), run against the published release
candidate `0.2.0-rc.2` of **Generated Secrets Operator**. This release is the
rename of SecretSpec Operator to Generated Secrets Operator; only the names
change (group `generatedsecrets.jabbas.eu`, kind `GeneratedSecret`, short name
`gensecret`, namespace `generated-secrets-system`, labels `owner-name` /
`owner-uid`, metrics prefix `generated_secrets_`). There is no other API or
behaviour change, so this test is a repeat of the 0.1.5 scenarios under the new
names, plus the new-name checks (scenario l). This candidate is also the one the
final `0.2.0` is to be **promoted** from (ADR 0005): the final tag must publish
this exact image digest without a rebuild. No secret value appears in this
report; comparisons are equal/changed verdicts, short digests of stored values,
or match counts only.

`0.2.0-rc.1` was **superseded** by `0.2.0-rc.2` and never ran in the home lab;
nothing of it was tested.

### Conflict requeue timings (scenario a)

UTC, 2026-11-15. The scenario was run twice; the second run is the measured one.

**Run 2 (measured).** The GeneratedSecret `dashboard-auth` was deleted (its
Secret went with it, default `deletionPolicy: Delete`), an unlabelled Secret
`dashboard-auth` was created, then the `traefik-basic-auth` example applied.

| Time | Event |
|---|---|
| 13:14:15 | GeneratedSecret created; `Ready=False`, `Conflict`. |
| before 13:15:07 | Foreign Secret deleted (`kubectl delete … --wait` returned; shell `date` right after it: 13:15:07). |
| 13:15:15 | `Ready=True` (`lastTransitionTime` 13:15:15, reason `Generated`). |

Recovery came **≤ 8 s after the confirmed deletion**, 60 s after the first
`Conflict`: the 60 s requeue, well within 90 s. No restart, edit or manual nudge.

**Run 1 (not used for the figure).** All 7 examples applied at 13:02:17 with a
foreign `dashboard-auth`; `Conflict` at 13:02:17. The operator log then shows
`Conflict` on every 60 s requeue (13:03:17 … 13:10:17) and `Apply` / `Ready=True`
at 13:11:17. This is **not** a slow recovery: the delete of the foreign Secret
was issued in a tool-call batch together with a `date` (which printed 13:02:21),
but the delete itself was held back by the session's permission prompt and ran
only between 13:10:17 and ≈ 13:10:55 (the next batch's `date`). The next requeue
after the real deletion recovered. The `13:02:21` stamp did not describe the
delete, so run 1 was repeated with sequential commands (run 2). This is an
inference from the log and clocks, not a measured delete second.

### Log-leak check (scenario i)

Pattern files were written by redirect under `$TMPDIR/opencode/hl-020rc2/`; only
counts were ever printed. Set A was built once all 7 GeneratedSecrets were Ready
(after scenario a, before c) and **before** scenarios d, e and g replaced

(31 lines, whole log of the first pod) and the post-restart log (24 lines, the

values), so the technique finds values that are present.

## Deviations and notes

- **Scenario a was run twice** (see the timing section): the first run's delete
  of the foreign Secret was held back by a permission prompt, so its
  `Conflict`-to-`Ready` interval (≈ 9 min) is an artefact of the test session and
  not an operator delay. The second run gave the real figure.
- **No current kubectl context** is set on the test machine (`kubectl config view
  --minify` fails with `current-context must exist`); the target check used
  `--context admin@k8s` (`https://kube.home:6443`), as every command did.
- **Metrics:** `generated_secrets_reconcile_total` is absent from `/metrics`
  while the operator has not reconciled anything yet (a labelled counter without
  series), so the first read on the idle pod showed the other new names and the
  counter only appeared after the scenarios.
- **Digest snapshots** used a `while read` loop around `shasum` to print only
  `<key> <digest16>` (macOS `cut` has no long options, so `cut -c 1-16`).
- **`LowEntropy` Warning Event** on `garage` (`access-key-id`, 96 bits) from the
  example, as designed.
- The HTTP chart repository was exercised by Flux (before this run); the OCI
  chart was exercised through `cosign verify`.
